# AGENTS.md

Instructions for AI coding agents working in this repository. Humans should read
[CONTRIBUTING.md](.github/CONTRIBUTING.md) first; everything here applies to you too.

Before opening a pull request, read [REVIEW.md](REVIEW.md). It lists the
invariants reviewers check, and your PR will be held to them.

## Ground rules

- A human is accountable for every change. The person submitting the PR must
  understand it, have run the checks below, and have signed the
  [CLA](https://cla-assistant.io/bufbuild/protovalidate-es).
- Call out every public API change in the PR description. New exported APIs
  should be discussed in a GitHub issue first.
- Keep PRs small and focused. Do not mix refactors, formatting, or dependency
  bumps into a functional change.
- Do not "clean up" code you were not asked to change.

## Environment

- Node.js version from `.nvmrc`, npm version from `package.json`
  (`packageManager`), and a current Go toolchain for the conformance runner.
  Use `npm ci`, never `npm install` without a reason.
- Tasks run through turborepo. Scope to a package with `-F`, for example
  `npx turbo run test -F @bufbuild/protovalidate`.

## Commands

| Task | Command |
|---|---|
| Install | `npm ci` |
| Test and lint (run before every PR) | `npx turbo run test lint` |
| Typecheck | `npx turbo run typecheck` |
| Format | `npx turbo run format` |
| Regenerate generated code | `npx turbo run generate` |
| License headers | `npx turbo run license-header` |
| Conformance | `npx turbo run test -F @bufbuild/protovalidate-testing` |
| Conformance, CEL only | `PROTOVALIDATE_DISABLE_NATIVE_RULES=1 npx turbo run test -F @bufbuild/protovalidate-testing` |
| Type exports check | `npx turbo run attw` |
| Benchmarks | `npx turbo run bench -F @bufbuild/protovalidate-bench` |

CI fails if regenerated, reformatted, or re-headered output differs from what
is committed. Run the relevant command and commit the result.

## Files you must not hand-edit

- Anything under `packages/*/src/gen`: generated by `protoc-gen-es`. Change the
  `.proto` input, then regenerate.
- `packages/protovalidate/proto`: copied from upstream protovalidate at the
  version in `packages/upstream/version.txt`. Do not edit it here.
- `packages/upstream/version.txt`: bumping the upstream version is a
  maintainer task. It changes the protos, the conformance suite, and the README.
- `packages/protovalidate-testing/expected-failures.yaml`: adding an entry
  hides a conformance regression. Fix the bug instead.

## Code standards

Biome enforces formatting and lint. Do not argue with it or disable rules
inline. Beyond that:

- **Dependencies.** `@bufbuild/protovalidate` depends only on `@bufbuild/cel`
  and `@bufbuild/re2`, pinned to exact versions, plus a peer dependency on
  `@bufbuild/protobuf`. Do not add dependencies without maintainer agreement.
  Do not use `@bufbuild/protobuf` APIs newer than the peer dependency range.
- **Imports.** Relative imports use the `.js` extension, even in `.ts` files.
  No default exports.
- **Dual ESM and CommonJS.** The package ships both. Do not use `import.meta`,
  top-level `await`, or anything else that breaks the CJS build. `attw` must
  pass.
- **No side effects.** The package declares `"sideEffects": false`. Module top
  level must not mutate globals, register anything, or do work beyond defining
  constants, functions, and classes.
- **Portability.** The runtime must work in baseline browsers, all maintained
  Node.js releases, Deno, and Bun. Do not use `node:*` imports, `Buffer`, or
  `process` in `packages/protovalidate/src` outside of tests.
- **Bundle size.** The package is used in browsers. Treat added code as a cost
  the change must earn.
- **TSDoc.** Exported symbols get TSDoc comments in the style of their
  neighbors.
- **License header.** Every new source file needs the Apache 2.0 header.
  `npx turbo run license-header` adds it.

## Validation correctness

protovalidate-es passes the upstream protovalidate conformance suite in strict
mode. Every change must keep it that way.

- **Sources of truth, in order:**
  1. The upstream conformance suite at the version in
     `packages/upstream/version.txt`.
  2. The rule definitions and their CEL expressions in
     `packages/protovalidate/proto/buf/validate/validate.proto`.
  3. Behavior of [protovalidate-go](https://github.com/bufbuild/protovalidate-go),
     the reference implementation.

  Never resolve an ambiguity by intuition. If the spec and upstream behavior
  disagree, upstream behavior wins; say so in the PR.
- **Native rules and CEL must agree.** Many standard rules have a native
  implementation in `src/native` that replaces the CEL expression from
  `validate.proto`. Both paths must produce the same violations, including rule
  IDs, messages, and field and rule paths. Conformance runs on both paths in CI.
- **Violations are a contract.** Conformance checks violation IDs, messages,
  and paths exactly. Do not change them unless upstream does.
- **Validation runs on untrusted input.** Keep evaluation cost linear in the
  size of the message. Regular expressions go through the RE2 engine, never
  the JavaScript `RegExp` engine. Respect the bound on collected violations.

## Tests

See the Tests section of [REVIEW.md](REVIEW.md). In short: `node:test` and
`node:assert`, tests live next to the code as `*.test.ts`, and bug fixes need
a test that fails without the fix.

## Pull requests

- **Title:** start with a capitalized verb in the imperative ("Add", "Fix",
  "Remove"), first word not ending in "s" or "ing", no trailing punctuation, no
  contractions. Conventional-commit prefixes like `feat:` or `fix:` fail CI.
- **Description:** what changed, why, and how it was tested. Link the issue.
  Call out any public API change, violation change, or new expected failure
  explicitly. For performance changes, include benchmark results.
- Do not add the `Emergency Bypass Review` label. It is for maintainers only.
